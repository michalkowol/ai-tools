Briefing plan: checkboxes saved in localStorage

The day plan page (~/.ai/worklog/plans/*.html) gets checkboxes next to its items. The state is saved in localStorage, so it survives a page reload.

Context

The day plan from /daily-workflow:briefing is read-only today. The user wants to tick off on it what they have done during the day, without going back to the session for every item. The state must survive a page reload.

Facts

  • The page is built from plans/YYYY-MM-DD[-home].json by worklog render-plan; every value is escaped, only http(s) links are kept, the CSS is inline, there are no scripts. plugins/daily-workflow/scripts/wl/plan.py
  • Lists are rendered by one function items() as <ol><li>; agendas and the daily sections by bullets() as <ul>. plan.py:67-76
  • Items usually have a title and source.url (tasks) or url (PRs). plan.py titled(), review(); skills/briefing/references/plan-schema.md
  • briefing update after the daily renders the same file again. skills/briefing/SKILL.md
  • The page is opened from file:// on the host (open …); localStorage works for file:// in Chrome and Safari. worklog.py host_path, the Inbox page uses localStorage the same way

Out of scope

  • Changes to the plan content and to the briefing rules outside the "done" mode.
  • Alpine.js and other JS dependencies.
  • Syncing between browsers or devices.
  • The Inbox page.

Decision log

What does "adding a checkbox" mean?

Every list item has a checkbox that can be ticked as done. Like A, plus an "+ add item" field at the bottom of a section where you add your own tasks with a checkbox (also in localStorage, they do not go to Notion).

Recommended option accepted. The checkboxes are for ticking off items the plan already has.

Which sections have checkboxes?

Today's tasks, Outside the limit, Code review order, My pull requests, Needs attention, Prep for tomorrow, Follow-ups. Agenda points in Meetings, to tick off topics already discussed. One checkbox next to the Deep Work block. Also For the daily, After the daily, Resolved and Notion changes, which are information, not tasks.

All options picked: every item on the page has a checkbox, including the meeting agenda, the Deep Work block and the information sections.

What happens to a ticked item?

The plan order does not change, what is done stays visible. Unfinished items are always on top, but the list jumps on click. The cleanest view, but done items have to be revealed.

Recommended option accepted. The plan order does not change.

How is an item recognised after the plan is rendered again?

Key = section + the item URL (or the title when there is no URL). A tick survives an update even when the item moves. Changing a title without a URL loses the tick. The simplest, but after an update ticks land on the wrong items.

Recommended option accepted. A tick survives briefing update, because the key does not depend on the position in the list.

Do ticks go back to Notion?

The checkboxes are a handy list for today. Statuses in Notion are changed as before. The page builds a prompt /daily-workflow:briefing done … with the ticked Notion cards, you paste it into the session and the skill sets Done (today). More work: a new skill mode.

Ticks go back to Notion through a prompt pasted into the session; details in D7–D10.

Where does the checkbox script live?

A small script in <script> next to the CSS in plan.py. The page stays one file, old plans get it too after a re-render. A JS file in the plugin, copied to plans/assets/ on render. Consistent with the Inbox, but the page is now several files.

(if you need to do something complicated and it makes the code easier, you can also use https://alpinejs.dev/)

The script and the style are plugin assets copied on render, like the Inbox. Alpine.js is not needed: checkboxes, localStorage and building the prompt are a few dozen lines of plain JS in light DOM (like inbox-components.js), without a dependency that would have to sit locally in the assets for file://.

What goes into the "Copy done" prompt?

Ticked items whose link leads to a Notion card (tasks, Deep Work, Follow-ups). The skill sets their Status to Done (today). Reviews, PRs, the agenda and the information sections are ticked off only locally. The prompt holds every ticked item; the skill changes the Notion cards and only lists the rest in the answer. A longer prompt with no extra effect.

Every ticked item goes into the prompt: Notion cards get Done (today), the rest is listed in the answer and, per D9, marked done in the plan JSON.

Is the pasted prompt enough consent to change Notion?

Ticking and pasting is the consent; the skill sets Done (today) without asking and answers with a short summary. Shows the list of changes and waits for "yes", like the changes in the morning briefing. Safer, one more step.

Recommended option accepted. The same consent model as the Inbox apply.

After "done", does the plan remember ticks outside localStorage too?

The skill writes done: true to the items in plans/<date>.json and renders the page again. The items are ticked in another browser too and after localStorage is cleared. The plan JSON does not change. Simpler, but the state lives in one browser only.

Recommended option accepted. The JSON stays the source of truth for what was done.

Where is the "Copy done" button?

A sticky bar appears when at least one Notion card is ticked: "N done · Copy done". Like the shortcut bar in the Inbox. A "Done today" section with the list and the button under Notion changes. Does not cover content, but needs scrolling.

Recommended option accepted. With D7 the bar appears when at least one item is ticked.

How are plain-text items (agenda points, daily bullets) marked done in the plan JSON?

Plain strings cannot carry done: true, so worklog plan-done adds their keys to done_items; object items still get done: true.

Found during implementation: converting the strings to objects would change the plan schema the briefing writes. The rest of D9 stays.
