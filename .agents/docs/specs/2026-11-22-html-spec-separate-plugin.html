Move html-spec-init out of mk into a separate plugin

Whether to move the html-spec-init skill from the personal mk plugin into its own marketplace plugin, so teams can install only the spec tooling.

Context

html-spec-init is the only skill in mk meant for teams: it copies the html-spec and html-spec-extract skills and the assets into a project, and those skills tell others to install mk. The rest of mk is personal commands, working-style skills and a hook that blocks risky commands. This is the same split that made daily-workflow a separate plugin.

Facts

Current state

  • mk has 9 commands, 10 skills and a PreToolUse hook for Bash (guard.sh) that blocks or asks to confirm risky commands. plugins/mk/commands, plugins/mk/skills, plugins/mk/hooks/hooks.json
  • The html-spec skill copied into projects tells people to install mk@michalkowol and run /mk:html-spec-init. templates/html-spec/SKILL.md lines 22-26
  • /mk:html-spec-init appears in 6 places: the templates of both skills, the headers of style.css and global-components.js, MIGRATIONS.md; plus the repo README. grep -rn mk: plugins/mk/skills/html-spec-init, README.md
  • 9 of 21 commits in the repo are about html-spec and usually bump the mk version (now 1.6.8). git log --oneline, plugins/mk/.claude-plugin/plugin.json

Effects of the move

  • Re-running the init overwrites the skills and assets in a project, so the old references to mk go away on their own. The spec format does not change, no spec migration is needed. html-spec-init/SKILL.md, MIGRATIONS.md
  • The note appended to CLAUDE.md / AGENTS.md does not mention mk. AGENTS.md
  • This project already has the skills installed with the old reference. .claude/skills/html-spec/SKILL.md line 22

Out of scope

  • Changes to the spec format, the components and the style.
  • Shipping html-spec as a plugin skill instead of copying it into the project.
  • The other skills and commands of mk.

Decision log

Move html-spec-init into a separate plugin?

Others install only the spec tooling, without the guard hook and the personal commands from mk. Spec changes do not bump the mk version. No work and one install for you, but every spec user gets all of mk.

The init is team tooling; installing it should not bring a personal hook and personal commands into other people's sessions.

What is the new plugin called?

The same name as the project skill and the spec format. Command /html-spec:init. Shorter, but generic and does not say it is about HTML. Tells the plugin apart from the html-spec project skill, but the command gets long.

One name for the plugin, the project skill and the format; the plugin prefix keeps the commands apart.

What is the init skill called in the new plugin?

The plugin prefix already says it is about specs, e.g. /html-spec:init. No rename, but the command repeats the name: /html-spec:html-spec-init.

Avoids repeating the plugin name in the command.

What stays in mk after the move?

Clean. Whoever runs the old command will not find it and installs the new plugin from the README. A small html-spec-init skill in mk that only says how to install the new plugin. Gentler, but has to be remembered and removed later.

Few users so far, and the README points to the new plugin; a stub would only be code to delete later.

Which version does the new plugin start from?

New plugin, new numbering. The spec format has its own number (html-spec format), so nothing is lost. Continuity with history, but a number unrelated to the new plugin.

The plugin version and the spec format are independent; a new plugin starts its own numbering.
