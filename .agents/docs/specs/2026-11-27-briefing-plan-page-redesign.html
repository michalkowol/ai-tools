Briefing plan page: html-spec style and web components

The day plan page (~/.ai/worklog/plans/*.html) gets the look of an html-spec spec and is built from web components, like the Inbox page.

Context

The user does not like the style of the plan page from /daily-workflow:briefing. It should look similar to an html-spec spec and use web components, like the Inbox page after its redesign. The current look, on the same fictional plan:

Facts

  • The page is built from plans/YYYY-MM-DD[-home].json in plan.py render(): concatenated HTML with the classes .top, .acts, li.chk, .k, .t, .deep-box; every value is escaped, only http(s) links. plugins/daily-workflow/scripts/wl/plan.py
  • plan.css has its own tokens (--bg, --ink, --line), sans-serif section headings, and the page header on a gray band. scripts/wl/assets/plan.css
  • plan.js is an IIFE without components: PlanLogic (tested with node --test) and the wiring of the .cbx checkboxes and the "Copy done" bar. The localStorage keys and the done prompt format stay unchanged. scripts/wl/assets/plan.js, tests/plan_logic.test.js
  • Inbox uses light DOM custom elements with an h() helper and its own CSS with the html-spec tokens. scripts/wl/assets/inbox-components.js, inbox.css
  • render-plan and render-inbox copy the assets on every render (plan.copy_assets). plan.py, inbox.py
  • Home mode uses the same page, without the work sections. skills/briefing/SKILL.md

Out of scope

  • The plan content, the JSON schema and the briefing rules.
  • Checkbox keys, localStorage and the done mode.
  • Alpine.js and other JS dependencies.
  • Dark mode.

Decision log

Which look for the plan page?

760 px column, serif headings, items split by rules like the Decision log, Deep Work with a vertical bar like a quote. Closest to html-spec, the fewest decorations. Every section is a white card with a border like the Inbox card, Deep Work in a card with a clay border, the three acts of the day as small cards. Sections are separated more clearly, but more borders. Header and the three acts of the day in a sticky left column, lists on the right. The shape of the day is always visible, but it needs a wide window (on a narrow screen the column drops to the top).

Combine versions B and C

The sticky side column from C and the sections as white cards from B. Details of the combination in D6.

How to build the page from web components?

Python writes <plan-page>, <plan-section>, <plan-item key url kind …> with the text inside (light DOM, styled by CSS). JS adds the checkboxes, the counter and the "Copy done" bar. The page is readable even without JS, escaping stays in Python. Content elements are hidden, <plan-app> draws the whole page in JS. Consistent with Inbox, but without JS the page is empty and more logic moves to JS. Python embeds the plan as <script type="application/json">, a component builds the page from it. The simplest Python renderer, but escaping and safe links move to JS.

Recommended option accepted. Escaping stays in Python, the page is readable without JS, and JS only adds the checkboxes, counters and the bar.

A shared style for the plan and Inbox?

A new assets/base.css with the html-spec tokens and primitives (.eyebrow, .tag, .btn, typography), copied to plans/assets/ and inbox/assets/. One place for the colors, but the change touches Inbox too. As Inbox does today. Inbox unchanged, but the same tokens in two files.

Inbox stays unchanged; the html-spec tokens are copied into plan.css, as in inbox.css.

What about the old pages in plans/?

worklog render-plan renders every plans/*.json in the folder again (the JSON is the source of truth, it takes milliseconds). Old pages always look like the new ones. New files (e.g. plan-components.js), the old plan.css/plan.js stay in the plugin. Old pages keep working the old way, but dead code stays. Only today's plan matters; old pages may break.

Recommended option accepted. The JSON is the source of truth, so every plan render refreshes the old pages too.

What else to add along the way?

"2/3" next to the section heading, counts the ticked items. Links to the sections under the header, useful for a long plan. A section with everything ticked collapses to its heading. Only the new look and components.

Recommended option accepted: a counter of ticked items next to the section heading, no section list and no collapsing.

Which combination of B and C?

The left column also holds the Deep Work card and the list of sections with counters as links. The day's progress and the most important block are always visible without scrolling; only lists on the right. Left column as in C, Deep Work as the first card on the right. A simpler column, but Deep Work disappears after scrolling.

Both variants: a sticky left column with the header and the three acts of the day as small cards (from B), sections as white cards on the right, the counter from D5 next to the section heading. On a narrow screen (below about 1100 px) the left column drops to the top of the page. The simpler column was picked: Deep Work stays the first card on the right.
